# AGENTS.md

Guidance for AI coding agents working in this repository: commands, architecture, conventions, and the non-obvious decisions behind the code. Keep it short - record *why* and *gotchas*, not what the code already says.

## What This Repository Is

AngleSharp.Renderer adds rendering on top of AngleSharp and AngleSharp.Css: a display-list renderer with a SkiaSharp backend that rasterizes HTML/CSS (and SVG) into PNG images.

## Commands

```bash
dotnet test src/AngleSharp.Renderer.sln                                      # full validation
dotnet test src/AngleSharp.Renderer.Tests/AngleSharp.Renderer.Tests.csproj  # iterate on renderer behavior
./build.sh | ./build.ps1 | ./build.cmd                                       # Fallout bootstrapper
```

The renderer and test projects target `net8.0` and `net10.0`; both runtimes are exercised.

## Architecture

- `HtmlRenderer` builds a `DisplayList` from the AngleSharp.Css render tree and computed styles. All layout lives in this partial class: `HtmlRenderer.cs` (block/flex/grid/table layout, style maps, painting), `HtmlRenderer.Inline.cs` (flow children, inline formatting context, bidi reordering, intrinsic sizing), `HtmlRenderer.Text.cs` (`hyphens`, `tab-size`, small caps, `font-stretch`, `DrawStyledText`), `HtmlRenderer.Floats.cs` (floats, `clear`, block formatting contexts), `HtmlRenderer.Columns.cs` (multi-column layout), `HtmlRenderer.Tables.cs` (tables), `HtmlRenderer.Sticky.cs` (`position: sticky`), `HtmlRenderer.WritingModes.cs` (`writing-mode`).
- `DisplayList` is the backend-agnostic, flat command model. Scoped effects are push/pop pairs (`PushClip`, `PushTransform`, `PushOpacity`, `PushFilter`, ...) that the backend maps to `Save`/`SaveLayer`/`Restore`. `InsertRange` and `MoveRangeToEnd` exist to reorder already-emitted commands.
- `SkiaRenderBackend` rasterizes the display list and implements `ITextMeasurer`, so layout measures with the very typefaces it paints with.
- `ITextMeasurer` is the seam between layout and rasterization (line breaking, alignment, table widths). Never reintroduce a font-independent width heuristic - it silently decouples layout from what is drawn.
- `SkiaTextShaping` is the single font-resolution path for both measuring and painting (and SVG text). Text is drawn glyph by glyph with `canvas.DrawText` - no HarfBuzz shaping (no Arabic joining, ligatures or `font-feature-settings`).
- `BidiAlgorithm` (UAX #9: levels, `unicode-bidi` embeddings/overrides/isolates, mirroring) and `WebFontDecoder` (WOFF via zlib, WOFF2 via Brotli plus the `glyf`/`loca`/`hmtx` transforms, back to plain sfnt) are self-contained internal helpers.
- `HtmlRenderOptions` holds viewport and text defaults.
- `SvgRasterizer` (`Skia/Svg/`) paints SVG by walking the DOM AngleSharp already produced - no second SVG parser. Its PNG output becomes an ordinary `RenderedImage`.
- `InteractiveHtmlRendererState` / `IDomHarness` back interactive documents (`:hover`, scrolling, focus, a virtual clock for transitions/animations/caret).

### Fonts

`SkiaTextShaping.CreateTypeface` walks the `font-family` list in order; the first usable entry wins:

1. Generic families (`serif`, `sans-serif`, `monospace`, `cursive`, `fantasy`, `system-ui`, `ui-*`) always map to the bundled fonts in `Resources/Fonts`. This is what keeps snapshots reproducible; `@font-face` cannot take them over.
2. `@font-face` rules (`FontFaceLoader`, carried on `DisplayList.Fonts`). `local()` resolves against installed fonts; `url()` against `data:` URIs, or the network only when the browsing context has an `IDocumentLoader`. WOFF/WOFF2 are decoded to sfnt by `WebFontDecoder` first; SVG and EOT fonts are rejected.
3. Installed families - host-dependent, never assert them in snapshots.
4. Bundled sans-serif as the last resort.

A character the resolved typeface has no glyph for falls back per character (`SplitFallbackRuns`, shared by measuring and painting): the next `font-family` entry that has it, then the bundled fonts, then `SKFontManager.MatchCharacter` (host-dependent, so never in snapshots). Text the typeface fully covers stays one run.

Never resolve named families with `SKTypeface.FromFamilyName`: it substitutes the host default for unknown names instead of returning null, swallowing the rest of the fallback list. Availability goes through a case-insensitive index of installed families (Skia's lookup is case-sensitive on Linux only).

## Upstream Policy (important)

**Never work around AngleSharp / AngleSharp.Css bugs locally.** Reproduce them with a failing test in the upstream project's own suite, fix them there, verify locally via a temporary `ProjectReference` to the sibling checkout, then revert to `PackageReference` once released. Wrong output in the meantime is acceptable. Current minimums: `AngleSharp` 1.8.5+, `AngleSharp.Css` 1.2.1+, set via `AngleSharpVersion`/`AngleSharpCssVersion` in the `.csproj` and the `ANGLESHARP_VERSION`/`ANGLESHARP_CSS_VERSION` env of `ci.yml` and `update-snapshots.yml` (which override the `.csproj`, so change all three together). Prefer delegating CSS grammar to AngleSharp.Css's public parsers (`TransformParser`, `FilterParser`, `GradientParser`, `GridParser`, `TimingFunctionParser`) and keeping only the conversion to backend-agnostic `Render*` types here. Hand-roll only what upstream genuinely lacks (e.g. `clip-path` basic shapes).

**Styling comes only from the computed style** (the render tree, cascaded with the UA stylesheet), never from tag names: no "`<b>` is bold", "`h1` is 700", "`<span>` is inline", "`<script>` is hidden". An unset `display` is its initial value, `inline`. Tag names are only legitimate for element semantics that CSS does not express (replaced-element content, form-control values, `<select>` options, `ol`/`li` ordinals). When the UA sheet lacks a rule, file it upstream as a failing test.

Upstream status: everything filed so far is fixed as of 1.2.1; no failing upstream tests are open.

## Core Layout Invariants

- **Box paints behind children.** An auto-sized box's height is known only after its children are emitted, so `LayoutElement`/`LayoutFlexContainer`/`LayoutGridContainer` capture `boxPaintInsertIndex`, build the box's own background/shadow/border/outline into a scratch `DisplayList`, and splice it in with `InsertRange`. Painting order per box: (transform → blend → opacity → filter → clip-path scopes), background, `box-shadow`, border, outline, then the `overflow` clip, then children. Pops for clip/filter/opacity/transform are appended after children, innermost first.
- **Paint order = layout order.** `OrderChildrenForPainting` decides the order children are *laid out* too (it threads `cursorY`). Do not reorder it to fix paint stacking; relocate emitted commands instead (`MoveRangeToEnd`, as `position: sticky` does).
- **An authored `height` is the height** of block and flex containers; in-flow content overflows it (only `min-height`/`max-height` clamp it). Auto heights come from the laid-out content.
- **`box-sizing`** is converted in exactly one place, `ResolveAuthoredDimension`; everything downstream works in content-box sizes. Flex item sizes are already converted before `ResolveFlexibleContentDimension` reads them - do not convert twice. Tables honor it too (their width goes through the same method); the HTML default `table { box-sizing: border-box }` has to come from the UA sheet.
- **Style maps.** `CreateStyleMap` builds a per-element `StyleMap` (string map plus a typed raw-length side channel used by `ParseLength`). Always go through `GetOrCreateStyleMap` (cached per render call in `LayoutContext.StyleMapCache`; the cache must never outlive one `BuildDisplayList`/`RenderToPng`/`CaptureLayoutMetrics` call or interactive state goes stale). Code writing directly into a length entry must call `StyleMap.ClearRawLength` for that key.
- **Explicit vs computed values.** `background-image`, `grid-template-*`, gaps and `grid-column`/`grid-row` are read from the cascaded-but-uncomputed declaration (`ResolveExplicitPropertyValue` via the cached `LayoutContext.StyleCollection`), because AngleSharp.Css's `.Compute()` resolves their percentages against the viewport instead of the element's box. `width`/`height`/`min-*`/`max-*` take the explicit value only when it contains a `%`; anything else (`em`, `rem`, `vw`) needs the computed one.
- **The page.** `<html>` is laid out as an ordinary block (so `<body>`'s UA `margin: 8px`, padding, border and width apply); `context.Padding` is 0. `PropagateToViewport` moves the root's background (or `<body>`'s, if the root has none) to the canvas and removes it from that element's style map, and drops their `overflow`. `<html>`'s metrics are re-recorded as the viewport, since it is the scrolling element. Structural tests in `HtmlRendererTests` run with a prepended `body { margin: 0 }` sheet (its `ParseAsync`). The vertical-page path still lays out `<body>`'s children directly.
- **Blockification.** AngleSharp.Css blockifies the computed `display` of floats, absolutely positioned boxes and the root, so they are never inline-level; handing one to an inline formatting context would lay it out again forever. Flex items are not blockified upstream (it does not know the formatting context), so `LayoutElement` forces them to block layout itself.
- **Margin collapsing** through first children is recursive (`TryGetFirstCollapsibleChildTopMargin`); a box whose margin its parent absorbed (`suppressNextBlockTopMargin`) absorbs the whole chain below it too. Floats and out-of-flow boxes are skipped; inline-level content (atomics included) stops the chain.
- **Unset ≠ initial.** AngleSharp.Css often reports an unset property as an empty string rather than its initial value; parsers fall back to the inherited value (inherited properties) or the CSS initial value.
- Adding a new `RenderPaint` (or other) subtype: check every place that pattern-matches on the existing ones (`PaintBackground` once silently dropped `RenderImagePaint`).
- **Flow layout.** `LayoutFlowChildren` (used by `LayoutElement` and the page itself) splits children into block-level children and runs of inline-level content. A run of bare text keeps the paragraph path (`LayoutTextNode`/`LayoutWrappedText`/`WrapText`); any run containing an element goes through `LayoutInlineFormattingContext`: the subtree is flattened into `InlinePiece`s (whitespace collapsed across element boundaries, break opportunities per piece), greedily broken into line boxes, and each line is emitted with one baseline (strut + half-leading per piece + atomic margin boxes). Inline boxes paint per line fragment; block-level boxes inside inline content get a line of their own.
- **Atomic inlines and shrink-to-fit.** Inline-blocks (and inline-flex/grid/table, form controls, `<img>`/`<svg>`) are measured by `TrialLayout`, which lays the element out into a scratch list under a temporary `LayoutCapture` (so real metrics capture is untouched) and reads its border box and last text baseline (`RecordTextBaseline`). Auto widths of atomics, floats and absolutely positioned boxes use `ResolveShrinkToFitBorderBoxWidth` (intrinsic widths from `ComputeContentIntrinsicWidths`), then `LayoutNode(..., forcedBorderBoxWidth, isAtomicInline)`. Nested inline-blocks multiply trial layouts, so keep the measurement paths cheap. A percentage `width` counts as `auto` in an intrinsic contribution (`ComputeOuterIntrinsicWidths`), since it would refer to the size being computed.
- **Pseudo-elements** proxy `LocalName`/`GetAttribute` to their host. Guard tag-based special cases (`ResolveFormControlKind`, `TryResolveImage`, `TryResolveInlineSvg`, `<svg>` checks) with `IPseudoElement`; replaced-element checks go through `IsReplacedElement`, which judges a pseudo only by an image in its own `content`. A pseudo's `TextContent` (and its host's) never includes generated content; read text from the render tree, as the inline collector does.

## Feature Notes

Only the non-obvious parts; see XML doc remarks in `HtmlRenderer.cs` for detail.

### Box model, positioning, painting
- Floats, `inline-block`, relative/absolute/fixed/sticky positioning, z-index ordering (CSS 2.1 Appendix E: a stacking context's own background paints before its negative-z descendants).
- `position: sticky` (`HtmlRenderer.Sticky.cs`): a sticky box is laid out at its natural position and registered (`LayoutStickyAwareElement`, wrapping every `LayoutElement` call) with the scope of the container laying out its parent; every container (block, flex, grid, table, page) calls `ResolveStickyBoxes` once its content box is known (after its own box-paint `InsertRange`). That shifts the box by `top`/`bottom`/`left`/`right` against the viewport (layout already runs in scrolled coordinates; `top` beats `bottom`, `left` beats `right`), keeps its margin box inside the container's content box, moves its commands to the end of the container's children under a `PushTransform` translation, and re-records its own metrics. Ranges are found again by the identity of their first command; registrations made against a scratch list (trial layouts, multi-column) are ignored, so such sticky boxes stay static. The viewport is the only scrollport. Below-the-fold culling (`maxY`) is skipped while a `bottom`-sticky box follows.
- Floats: each block formatting context owns a `FloatArea` (placed float margin boxes, absolute coordinates) that is passed down instead of the old offset/bottom pair. Ordinary blocks share their parent's area, so their *box* ignores floats while their lines (`GetBand` per line in the IFC; a bare-text run beside floats goes through the IFC too) wrap around them; boxes that establish a new context (`EstablishesBlockFormattingContext`: floats, positioned boxes, atomics, flex items, `overflow` other than `visible`, `flow-root`, flex/grid/table) get a fresh area, sit beside outer floats as a whole, never collapse margins with children, and grow to contain their own floats. `FloatArea.Place` puts a float as high as possible on its side, never above an earlier float, moving down when it does not fit. Floats and atomics keep their authored margins (no over-constrained margin absorption). `clear: left|right|both` uses `GetClearance`. Not modeled: lines moving down when even their first word does not fit beside a float.
- `min-width`/`max-width` clamp block widths (a clamped width centers with `margin: auto`). Replaced elements without a size use their natural size.
- On a box, `vertical-align` positions the box in its line only; it is reset for the box's own contents.
- `visibility: hidden` (and `collapse` outside tables) is a paint concern only: never use AngleSharp.Css's `IsVisible()` for layout (it rejects hidden boxes); use `GeneratesBoxes` (`display: none`). The inherited flag `RenderTextStyle.IsHidden` suppresses text (`DrawStyledText`), inline fragments, markers, form controls, images, column rules and, through `decorationBuffer`, a box's own decorations, while its scopes stay so visible descendants still paint.
- `border-radius`: shorthand and longhands, elliptical, as `RenderCornerRadii` (8 floats). `ClampToBox` applies the spec's single global scale factor. A uniform-width rounded border is one `StrokeRoundedRect`; mixed widths fall back to square corners. `outline` never rounds.
- `box-shadow`/`text-shadow`: parsed from AngleSharp.Css's normalized `rgba(...)` output (`ExtractColorToken`). Layers paint back-to-front in reverse order. Outset shadows are clipped out of the border box (`Difference`), inset ones clipped into it. Blur sigma = radius / 2 (a common approximation, not pinned by a conformance test).
- `overflow`: `hidden`/`scroll`/`auto`/`clip` clip at the padding edge (no scrollbars), as one rectangle for both axes, reusing the box radii. Border and outline are never clipped.
- `clip-path`: hand-rolled `circle()`/`ellipse()`/`inset()`/`polygon()` against the border box. No `url()`, `path()`, or box keywords (those disable clipping); `inset() round` takes a single uniform radius.
- `transform`/`transform-origin`: `TransformParser` + `ComputeMatrix`, converted to `RenderTransform2D` (CSS `matrix(a..f)` order). AngleSharp.Css's `TransformMatrix` is row-vector, so `M12`/`M21` are transposed (`M11→A, M21→B, M12→C, M22→D`). Functions post-multiply left to right. The origin pivot must be in absolute canvas coordinates. 3D functions are a permanent scope cut (no projection).
- `filter`: `FilterParser` gives function names; argument meaning (color matrices, blur, `drop-shadow`) is implemented here, independently of `SvgFilterBuilder`. Unknown functions and `url(#id)` are skipped. Painted via `SaveLayer`.
- `opacity`: group composite via `SaveLayer`, so overlapping children blend as one unit. `opacity: 1`, `transform: none` and empty `filter` push nothing.
- The whole-element effects (transform, blend mode, opacity, filter, clip-path, mask, backdrop-filter) are opened and closed by `OpenElementEffectScopes`/`CloseElementEffectScopes`, shared by blocks, flex, grid and table containers.
- `mix-blend-mode` and `isolation: isolate` are `PushBlendMode`/`PopBlendMode` scopes (a Skia `SaveLayer` with a blend mode) nested between transform and opacity. `background-blend-mode` blends the single image layer with the background color inside its own isolated group; the background color always paints under an image/gradient. `background-clip` insets the painted `FillRectCommand.Rect` to the padding or content box; `background-origin` (initial `padding-box`) sets `FillRectCommand.PaintArea`, the box an image/gradient shader is sized and positioned in (`SkiaRenderBackend.DrawFillRect` uses `PaintArea ?? Rect`).
- `outline-offset` grows (or, negatively, shrinks) the outline rect.
- Border styles: `dotted` (round dots), `dashed`, `double`, `groove`/`ridge`/`inset`/`outset` (bands across the thickness with a darker shade, `GetBorderBands`). Rounded borders other than uniform solid/dashed/dotted are painted per edge as `FillRingCommand`s (outer minus inner rounded rect, inner radii = outer minus border widths) clipped to the edge's trapezoid, so widths blend along the curve and colors meet on the diagonals; dashed/dotted rounded borders keep straight segments clipped to the outer curve.
- Backgrounds are a list of `BackgroundLayer`s (`ParseImageLayers`, shared with masks): each `background-image` item takes the matching item of `-size`/`-position`/`-repeat`/`-clip`/`-origin`/`-blend-mode` (lists repeat); layers paint bottom-up, the color under them clipped like the bottom layer. `RenderImagePaint.RepeatModeX/Y` carry `space`/`round`; a sized/positioned/repeated gradient gets a `RenderBackgroundTile`. The Skia backend tiles both through a recorded picture shader (`CreateTiledPaint`), which is how `space` gaps and `round` scaling work.
- `border-image` (`PaintBoxBorder`/`ResolveBorderImage`) replaces the border with a `DrawBorderImageCommand`: image or gradient source, slices (numbers or %), widths (numbers × border width, lengths, %, `auto`), outset, `stretch`/`repeat`/`round`/`space`, `fill`. Drawn as a nine-slice in `SkiaRenderBackend.DrawBorderImage`.
- Masks: `mask-image` layers (image/gradient) with `-size`/`-position`/`-repeat`/`-mode`/`-clip`/`-origin` (border box by default) become a `PushMaskCommand`/`PopMaskCommand` scope, innermost of the whole-element scopes; the backend composites the layers with `DstIn` (luminance via a luma color filter). `mask-composite` other than `add`, and `url(#svg-mask)` references, are not supported.
- `backdrop-filter` is a `DrawBackdropFilterCommand` emitted right inside the transform scope. SkiaSharp 2.x has no backdrop save-layer, so the backend snapshots the surface behind the box, filters it and draws it back clipped to the rounded border box; content inside a still-open ancestor layer (opacity, filter, mask) is not part of that backdrop.
- `translate`/`rotate`/`scale` compose before `transform` (`ToTranslateFunction` etc.), around the same `transform-origin`.
- `<img>` data: AngleSharp disposes a response right after processing it, so `<img>`'s `CurrentDownload` content is closed by paint time. `WithRendering()` registers `ImageResourceService` (`IResourceService<IImageInfo>`), which buffers the bytes per response; `TryLoadImageResource` reads them from there.
- Backgrounds: colors, `url(...)` images (`data:` or via `IDocumentLoader`, synchronous, shared per-document `DocumentImageCache` with `<img>`; failure falls back to `background-color`), `background-repeat`/`-position`/`-size` resolved at paint time in `CreateImagePaint`. `no-repeat` uses `SKShaderTileMode.Decal`, not `Clamp`. `space`/`round` act as `repeat`.
- Gradients: linear/radial/conic and `repeating-*` via `GradientParser`. Gotchas: Skia shader matrices map local → world space; `CreateSweepGradient` angles must stay within `[0, 360]` (rotation goes in the matrix); linear angles are shifted by -90° to Skia's convention in `ConvertLinearGradient`, conic does its own conversion; absolute-length stop positions stay unresolved (`AbsolutePositionPixels`) until the geometry is known. SVG gradients are a separate implementation.
- `aspect-ratio` derives width from a definite height; `object-fit`/`object-position` apply to replaced elements.

### Text
Every text feature exists twice - in the paragraph path (whole lines as strings) and in the inline formatting context (pieces) - so change both. `MeasureTextWidth` and `DrawStyledText` are the only measure/paint entry points: they drop soft hyphens, synthesize small caps (lowercase as uppercase at `SmallCapsScale` 0.7, run by run) and paint `text-shadow` first, so every path (cells, markers, form labels) agrees.
- `white-space`: `NormalizeWhitespace(text, mode)` implements the collapse/preserve table for the paragraph path; the IFC applies the same rules per piece (`\n` as forced breaks, `nowrap`/`pre` without soft wraps). Preserved tabs reach the next `tab-size` stop: an exact-width `IsTab` space piece in the IFC (runs split around it), expanded to whole spaces in the paragraph path (`ExpandTabs`).
- `text-align: justify` widens the line's untrimmed spaces (runs are then painted word by word); the last line and lines ended by a forced break use `text-align-last` (`ResolveLineAlign`), defaulting to start. Bidi-reordered paragraph lines are not justified.
- `hyphens`: soft hyphens (U+00AD) are break opportunities (`auto` = `manual`, no dictionary); a line broken there shows `-`. The IFC splits words into syllable pieces carrying `HyphenWidth`; `BuildLine` only takes a syllable when its hyphen fits too or the rest of the word fits.
- `text-overflow: ellipsis` (not inherited; only when overflow clips) and `-webkit-line-clamp`: the paragraph path truncates a single line by rune; the IFC truncates every overflowing line (`TruncateLineWithEllipsis`, by grapheme, keeping box edges) and stops after the clamped line, adding `…` when content remains.
- `word-break: break-all` wraps per character; `overflow-wrap`/`word-wrap: break-word`/`anywhere` split a word only when it cannot fit even an empty line. `keep-all` = `normal`.
- `text-transform` (inherited; `capitalize` tracks word starts across inline elements) and `word-spacing` (paints word by word, since a text run cannot express it). Runs drop their edge spaces unless decorated.
- `font-weight: bolder`/`lighter` (the UA rule for `b`, `strong`, `th`, headings) resolve against the inherited weight.
- `font-stretch` travels as a percentage on `RenderFont`/`DrawTextCommand` and selects an installed or `@font-face` width class; the bundled fonts have one width and nothing is synthesized.
- Bidi: the IFC builds the line text (atomics as U+FFFC, box edges as `unicode-bidi` controls or U+2060), runs `BidiAlgorithm` and splits pieces into visual fragments (`ReorderLine`); the paragraph path paints reordered lines as visual runs (`GetVisualRuns`). `direction` also resolves `start`/`end`.
- `text-decoration` (line/color/style), `letter-spacing`, `text-indent` (inherited; an inside list marker's space is the separate, non-inherited `MarkerIndent`), `vertical-align` shifts as fixed font-size fractions.

### Writing modes
`HtmlRenderer.WritingModes.cs`. Layout always runs horizontally in the logical coordinates of a *system* (x = inline, y = block). `ResolveWritingModeSystems` walks the render tree once per render and records the system every element's box sits in (`LayoutContext.BoxSystems`, also covering pseudo-elements, which have no parent in the DOM) and the system of its content (`ContentSystems`). A box in a vertical system gets its style map remapped to logical properties when it is built (`RemapStyleMapToLogical`: width↔height, min/max, margin/padding/border sides, insets, corner radii with swapped axes, overflow axes). An element whose writing mode is orthogonal to its box's system (or `<body>`'s content, for the page) is an orthogonal flow: its content is laid out at the origin with `RenderTextStyle.FlowMode` set to its own mode, inline size = its logical height or shrink-to-fit against the viewport, and wrapped in `ResolveOrthogonalFlowTransform` (box system⁻¹ · own mode, translated onto the content box); an auto width is the content's block size, and intrinsic sizing reports that block size (`MeasureOrthogonalBlockSize`). Orthogonal flows always establish a formatting context. Text in a vertical system turns with the system; `MeasureTextWidth`/`DrawStyledText` give upright glyphs (`text-orientation: upright`, or CJK etc. under `mixed`) one em each and counter-rotate them, and `vertical-lr` (a reflection) flips its sideways runs back about their glyph-box centre. Limitations: only orthogonal changes start a system (a `vertical-lr` element inside `vertical-rl` content keeps the outer direction); block containers only (flex/grid/table containers do not become orthogonal flows); backgrounds, gradients and shadows inside vertical content rotate with it; metrics of descendants are recorded in their flow's logical coordinates; sticky boxes inside an orthogonal flow stay static; no `text-combine-upright` and no decorations on upright glyphs.

### Lists, counters, generated content
- `display: list-item` uses normal block flow; `PaintListItemMarker` paints shape markers via the `border-radius` machinery and text markers via `DrawText`. Outside markers sit a fixed 6px left of the item's border box, inside the list's `padding-left` (40px from the UA sheet). Inside markers add the separate `MarkerIndent` to the first line.
- Ordinals: `ResolveListItemOrdinal` walks DOM siblings (`start`, `reversed`, `value`). General counters (`counter-reset`/`-increment`/`-set`, `counter()`/`counters()`) are also supported.
- `::before`/`::after` come from AngleSharp.Css's render tree (UA default `display: inline`). AngleSharp.Css stringifies counters, quote keywords and `url()` as empty (they need document state), so `ProcessCounters` re-reads the raw `content` in document order: `TryEvaluateGeneratedContent` rewrites the pseudo's text for counters and quotes (`GeneratedContentState.QuoteDepth`; `quotes`, or language defaults for `auto`/unset), and a `content` that is exactly one `url()` registers the pseudo in `s_generatedContentImages`, making it a replaced element. Images mixed with text (`"a" url(x) "b"`) replace the pseudo's single text child with text nodes and anonymous `img` render nodes (`ApplyGeneratedContent`; a detached `img` with initial styles), relying on AngleSharp.Css building a pseudo's children as a `List<IRenderNode>`.

### Flexbox and Grid
- Flexbox with grow/shrink/basis/wrap/alignment/order. Only the longhands (`flex-grow`/`-shrink`/`-basis`) are read, never the serialized `flex` shorthand. A definite `flex-basis` is used as-is; content is measured only for `auto` basis and size. `ResolveFlexibleLengths` is the spec's "resolve flexible lengths": hypothetical sizes clamped by min/max, the automatic minimum (`min-width: auto` = min-content, not for scroll containers), shrink weighted by inner base size, and freezing on min/max violations. Item heights (and column items' content size) come from a cached trial layout (`MeasureBorderBoxHeight`, `LayoutContext.MeasuredHeights`).
- Gaps (`ResolveColumnGap`/`ResolveRowGap`): `column-gap` percentages resolve against the content width, `row-gap` ones against a definite height, else zero.
- Grid: `GridParser` structural parsing; `fr`, `repeat()` (including auto-fill/auto-fit fill counts), `minmax()`, `grid-template-areas`, `grid-area`, `grid-auto-flow`, `grid-auto-rows`. `CssRepeatValue`/`CssFitContentValue` are internal upstream, so they are matched via `ICssFunctionValue.Name`. Sizing is two-pass: placement is resolved once in pass 1 (and reused, to keep the auto-placement cursor consistent) while `Auto` tracks grow; `fr` space is distributed between passes; without a definite height, `fr` rows get the flex fraction their items need (`ResolveIndefiniteGridFractionTracks`). An authored container height is the height (content overflows). Line names come from `[name]` in the track lists and `area-start`/`area-end` of `grid-template-areas` (`GridLines`); `ParseGridLinePlacement` reads numbers, negative numbers, names (with index) and `span` on either side. Content-sized columns (`auto`, `min-content`, `max-content`, `fit-content()`, `minmax()` with a non-`fr` maximum) are sized by `ResolveIntrinsicGridColumns` from the items' min/max-content contributions (`ComputeOuterIntrinsicWidths`): base size and growth limit per track, spanning items spread their excess, free space grows tracks to their limits and then stretches `auto` tracks unless `justify-content` packs them (track alignment itself - `center`, `space-between`, ... - is not implemented). Auto rows take authored item heights up front and measured content heights between the passes. `justify-self`/`align-self` (falling back to `justify-items`/`align-items`) place an item start/center/end/stretch; a non-stretched item is shrink-to-fit wide or content tall.

### Multi-column
`column-count`/`column-width`/`column-gap` (`normal` = 1em)/`column-rule` on block containers. Content is laid out once at the column width into a scratch list while recording line/block bottoms (`RecordColumnBreakCandidate`) and line tops (`RecordColumnContentStart`); the smallest column height that fits into the column count without splitting a line is chosen, and each column replays the scratch list under a clip plus translate (margins at a break are truncated). An authored height fills columns sequentially. No `column-span`, `break-*` or `column-fill`.

### Tables
`HtmlRenderer.Tables.cs`. Structure comes from computed `display` (header-group rows first, footer-group rows last); only `colspan`/`rowspan`/`span` are attributes. `GetTableStructure` runs once per render (`LayoutContext.TableStructures`) because the collapsing border model rewrites style maps: each grid line takes the widest border meeting there (`hidden` suppresses it), cells and the table keep half of each line as a transparent border for layout, and `PaintCollapsedBorders` paints the lines (solid only) over the cells; a collapsed table has no padding. Column widths: automatic layout (per-column min/max-content, spanning cells spread their excess by max-content, the table shrink-to-fit unless it has a width) or `table-layout: fixed`. Cells go through `LayoutNode` with `forcedBorderBoxWidth`/`forcedBorderBoxHeight` (stretched to their rows) and `contentOffsetY` for `vertical-align`; `baseline` cells share the row's first baseline (`TrialLayout`'s `FirstBaselineY`). Column-group/column/row-group/row backgrounds paint per cell. `visibility: collapse` on rows/columns (and their groups) removes them and their spacing after the column widths are computed; cells living only there are not laid out. `empty-cells: hide` skips an empty cell's box and the part backgrounds behind it (separated model only). Percentage row and cell heights refer to the table's definite height, else count for nothing; cell percentages are moved out of the cell's style map (`TableCellInfo.PercentHeight`) so `LayoutElement` never resolves them against a width. Tables get no transform/opacity/filter scopes. Not implemented: anonymous table objects (stray cells and text are dropped), percentage table heights.

### Form controls
- A form control's look (border, padding, background, margins, round radio) comes from the UA stylesheet. `ApplyFormControlDefaults` only fills in the element-derived intrinsic size (text fields 150px, checkbox/radio from font size, buttons/selects/file inputs from their label) when `width`/`height` are unset.
- `PaintFormControl` paints values, labels, the selected option, checked fills, color swatches, range track/thumb and file inputs; `<option>`s and button labels are excluded from child layout. `<textarea>` flows its text normally, unless its live `Value` differs from its child text: then the children are skipped and the value is painted. State is always the live DOM state (`IHtmlInputElement.Value`/`IsChecked`, `IHtmlOptionElement.IsSelected`), never the attributes. Placeholders paint with the computed `::placeholder` style (`ResolvePlaceholderTextStyle`, via `LayoutContext.StyleCollection`; the UA sheet gives it `color: darkgray`). `type=hidden` gets no chrome (hiding it is the UA sheet's job).
- `input[type=image]` is a replaced element when its `src` loads, else a button labelled with `alt` (default "Submit"). The date/time family (`FormControlKind.DateTime`) shows its value formatted as en-US browsers do (`FormatDateTimeInputValue`; invalid values show the segmented placeholder) beside a calendar or clock icon (`PaintPickerIcon`). `accent-color` (read from the style map, `auto` = `FormControlAccentColor`) colors checked checkboxes/radios and the range thumb.
- Labels center on ink using `FormControlTextAscentRatio`/`DescentRatio` (font-size fractions measured from the bundled font). The select arrow glyph `⌄` has its own vertical correction.
- A focused text input / textarea shows a caret (focus read from `IElement.IsFocused`) that fades via `IDomHarness.CurrentTime`; without a harness it is fully opaque.

### Interactivity and scrolling
- Page scroll: `RenderToPng`/`BuildDisplayList` shift layout by the root scroll offset only when a harness already exists (`TryGetDomHarness`, never `GetDomHarness`, which throws without an `IRenderDevice`). `CaptureLayoutMetrics` never applies the offset (scroll extents must be scroll-independent) and lays out the full page (`measureFullExtent`).
- `:hover` uses AngleSharp.Css's `SetPseudoClass`, which does not propagate; `UpdateForcedHoverChain` forces the whole ancestor chain and tracks it to un-force later.
- `CssTransitionTracker`/`CssAnimationTracker` run on a virtual clock (`IDomHarness.AdvanceTime`). Only `CssValueInterpolation.InterpolatableProperties` (colors, lengths, `opacity`, and the function lists `transform`/`translate`/`rotate`/`scale`/`filter`/`backdrop-filter`) interpolate; `all` means that whitelist. Function lists interpolate by structure (`CssFunctionListInterpolation`: matching functions argument by argument, `none`/shorter lists padded with identity functions, mismatched transforms through 2D matrix decomposition, anything else discretely at 50%). An element's natural `transform` is its authored value (`ReadAuthoredTransform`), never the computed one. Overrides are injected by `ApplyActiveTransitionAndAnimationOverrides` over the whole whitelist (not only existing keys); the animation lookup re-runs the cascade per property, so it only happens for elements whose computed style has an `animation-name`. Transition "from" values must be captured before pseudo-class mutation. Reversals restart with the full duration. Animations start at clock zero; fill-mode/direction/iteration share one effective-time computation; `animation-play-state: paused` is supported.

### SVG
`<img src="*.svg">` (sniffed in `TryLoadImageResource`) and inline `<svg>` (rasterized from the live DOM, cached per element). Rasterized at natural size × `OversampleFactor`, not at CSS size. Supports shapes and full path data, percentages, `g`/`a`/`use`/`symbol`/nested `svg`, `text`/`tspan`, `clipPath`, `mask`, gradients, patterns, filters (every primitive, with the filter region and primitive subregions as crop rects, each primitive in its `color-interpolation-filters` space (linearRGB by default, converted with lookup tables since SkiaSharp 2.88 has no gamma color filters) - see `SvgFilterBuilder`), `currentColor`, `preserveAspectRatio`, and an internal `<style>` subset. Inline SVG also takes the page's CSS (`ResolveSvgPageStyle`): the root starts from its computed inherited values (so `color`/`fill`/fonts flow in from the HTML), and each element's own page declarations (`ComputeExplicitStyle`, never `GetDeclarations`, which merges in inherited values that would beat presentation attributes) apply after the SVG-internal rules and before inline `style`. The inline-SVG raster cache is keyed by a fingerprint of the markup and those page styles. An SVG used as an image (`<img src="*.svg">`, CSS `url()`) is an isolated document, so - as in browsers - page CSS never reaches it. `SvgTransformParser` must apply the rightmost function first (`next.PostConcat(result)`) - verify changes there visually.

## Known Gaps

- Text shaping (HarfBuzz): Arabic joining, ligatures, kerning, `font-feature-settings`, `font-variant-*` beyond caps. Hyphenation dictionaries (`hyphens: auto`). `-webkit-line-clamp` counts lines per inline run, not across nested blocks.
- Not implemented: 3D transforms, `background-clip: text`, `mask-composite` other than `add`, the table features listed under Tables.

## Tests And Snapshots

- Structural tests: `HtmlRendererTests.cs` (and `TableSpanTests.cs`, ...) assert on the display list.
- Visual tests: `VisualConformanceTests.cs` compares PNGs against `verification-assets/`; `CaseRenderingTests.cs` renders full pages from `cases/`. Failures write actual + diff images to `failure-assets/` (diagnostics, not source of truth).
- Missing baselines are auto-created unless `ANGLESHARP_SNAPSHOT_STRICT=1`/`true` (CI always sets it). `ANGLESHARP_SNAPSHOT_UPDATE=1` overwrites the current platform's baselines.
- Update or add tests first when changing renderer behavior.

### Platform matrix

Baselines are per platform (`<name>.linux.png`/`.windows.png`/`.macos.png`) because FreeType, DirectWrite and CoreText anti-alias the same bundled font differently. `SnapshotBaselineCoverageTests` fails everywhere when a variant is missing. CoreText's anti-aliasing also drifts between macOS releases, so a Mac newer than the `macos-14` runner differs from its baselines on glyph edges; on macOS only, `VisualSnapshotVerifier` therefore accepts differences up to 64 levels on edge pixels (a neighbor differs in the baseline), while flat areas keep the test's own tolerance. `ci.yml` runs on pinned `ubuntu-22.04`/`windows-2022`/`macos-14` (bumping one means regenerating baselines). Flow: change code, refresh your own platform's baselines locally, push, then dispatch the **Update Snapshots** workflow (`update-snapshots.yml`) on the branch for the other two. Its bot push does not retrigger CI.
